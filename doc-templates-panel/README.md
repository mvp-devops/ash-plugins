# doc-templates-panel — Шаблоны документации для DeepSeek Harness

Плагин DSH, добавляющий в **левую боковую панель Web UI** отдельную панель
«**Шаблоны документации**»: создание, просмотр, редактирование, дублирование и
удаление шаблонов проектной документации, генерация готовых документов из
переменных, сохранение в `<workspace>/docs/`, поиск, фильтры, импорт и экспорт.

Плагин полностью локальный: без сети, облачных сервисов, телеметрии и CDN.

---

## Возможности

- **Панель в левой навигации** — элемент «Шаблоны документации» (`sidebar.panellist`, id `doc-templates`) и основная панель (слот `main`), как у штатных панелей DSH. Работает на узкой ширине, поддерживает клавиатурную навигацию (стрелки/Enter по списку, Escape в диалогах) и aria-атрибуты.
- **Два уровня шаблонов** — глобальные (доступны во всех проектах) и проектные (привязаны к рабочей директории сессии; хранится только стабильный хеш каталога, без абсолютных путей).
- **8 встроенных read-only шаблонов** на русском: «Требования к функциональности», «Нефункциональные требования», «Техническая спецификация», «Схема архитектуры» (с Mermaid-блоками), «Технический проект / Design Document», «Тест-кейс», «Протокол тестирования», «Чек-лист приёмки». Любой можно продублировать и править копию — встроенные никогда не перезаписываются при обновлении плагина.
- **CRUD и удобства** — создание, редактирование метаданных и содержимого, дублирование, удаление с подтверждением, поиск по названию/описанию/тегам/содержимому, фильтры по типу/области/тегам, сортировка по названию и дате изменения, группировка по типам, экспорт отдельного шаблона.
- **Свои типы документации** — кнопка «Типы…»: добавляйте, переименовывайте и удаляйте пользовательские типы (например «Пользовательская история»); встроенные типы неизменяемы; тип нельзя удалить, пока его используют шаблоны; типы входят в экспорт/импорт и в agent-инструменты (`doc_templates_type_*`).
- **Панель форматирования в редакторе** — кнопки как в Markdown-редакторах: полужирный, курсив, код, H2/H3, маркированный и нумерованный списки, чек-лист, цитата, таблица, блок кода, плейсхолдер `{{…}}`, ссылка, разделитель — применяются к выделению в тексте.
- **Корректные цвета темы** — панель использует официальные токены DSH (`--dsw-alias-button-primary-fill` + `--dsw-alias-brand-text` для основных кнопок, `--dsw-alias-label-*` для текста), поэтому кнопки читаемы и в светлой, и в тёмной теме (в светлой теме токен `brand-primary` — почти белый, использовать его как фон с белым текстом нельзя).
- **Просмотр с подсветкой Markdown** — безопасный минимальный рендер: пользовательский ввод экранируется, произвольный HTML/JS не исполняется, ссылки ограничены `http/https/mailto`, плейсхолдеры `{{…}}` подсвечиваются, Mermaid-блоки показываются как код.
- **Генерация документов** — форма переменных (`{{placeholder}}`, обязательные с проверкой, значения по умолчанию, автоподстановка `{{date}}` и `{{project_name}}`), предпросмотр результата, копирование в буфер обмена.
- **Сохранение в `<workspace>/docs/`** — каталог создаётся штатной файловой службой DSH, имя файла `<Название>_<ГГГГ-ММ-ДД>.md`, при конфликте — суффикс `_2`, `_3`… Перед записью панель показывает итоговый **относительный** путь и требует подтверждения; режим `dryRun` возвращает путь без записи.
- **Импорт / экспорт** — экспорт выбранного или полного набора в переносимый JSON (формат `doc-templates-panel/templates`, JSON Schema в `schema/doc-templates.schema.json`), импорт с предпросмотром diff и стратегиями `merge | overwrite | skip-existing | create-copy`, импорт шаблона из `.md`/`.txt`, восстановление хранилища из резервной копии.
- **9 agent-инструментов** и сессионная команда `/doc-templates` (см. ниже).

## Установка

### Вариант 1. CLI

```bash
dsh plugin --profile <имя-профиля> add ./doc-templates-panel
```

Затем перезапустите DSH, если профиль применяется только при старте.

### Вариант 2. Plugin Manager / tool `plugin_manager`

В Web UI: **Настройки → Плагины → Добавить плагин → Локальный каталог**, укажите
путь к каталогу `doc-templates-panel`. Или через инструмент:

```
plugin_manager install_bundle target=<абсолютный путь к каталогу doc-templates-panel>
```

Bundle не требует сборки и внешних зависимостей (чистый ESM; клиентская часть
использует React из базовой таблицы модулей браузерного загрузчика DSH).

## Локальная разработка через `--patch`

Запуск DSH с патчем подхватывает плагин из исходников без установки в профиль:

```bash
dsh --patch ./doc-templates-panel/cordis.patch.yml
```

Правки `client.js` подхватываются перезагрузкой страницы (HMR клиента DSH);
правки host-части требуют перезапуска сессии/хоста. Тесты и проверка типов:

```bash
npm test            # node --test tests/
npx tsc --noEmit    # проверка JSDoc-типов (опционально)
```

## Хранение и переносимость

| Данные | Где живут | Перенос |
|---|---|---|
| Встроенные шаблоны | внутри пакета плагина (read-only) | вместе с плагином |
| Пользовательские шаблоны | `$DSH_PROFILE_DIR/doc-templates-panel/templates.json` (иначе `$DSH_HOME/doc-templates-panel/`) | экспорт/импорт JSON |
| Резервные копии | рядом с `templates.json`: `doc-templates.backup-<timestamp>.json` | вручную или восстановлением |
| Повреждённый файл | сохраняется как `doc-templates.corrupt-<timestamp>.json` | — |
| Сгенерированные документы | `<workspace>/docs/` | как обычные файлы проекта |

- Запись **атомарная** (tmp + rename). Повреждённый JSON не роняет плагин: файл
  сохраняется рядом, выполняется восстановление из самой свежей копии, а панель
  и `/doc-templates status` объясняют, что произошло и как восстановиться.
- `schemaVersion` мигрируется автоматически; **перед миграцией** создаётся
  резервная копия, при неудаче исходные данные восстанавливаются, ошибка
  показывается по-русски. Документ из более новой версии схемы не портится —
  плагин предлагает обновиться.
- Не хранятся секреты, токены и абсолютные пути: проектная привязка — это хеш
  каталога (`projectId`) плюс имя каталога (`projectName`).
- Обновление плагина не перезаписывает пользовательские шаблоны: они живут в
  отдельном JSON, встроенный слой читается из кода.

### Перенос между двумя компьютерами

1. **Компьютер А**: панель → «Импорт / экспорт» → «Экспортировать все шаблоны» —
   скачается `doc-templates-export.json` (или `/doc-templates export {"all":true}`).
2. Передайте файл любым способом (он не содержит секретов и абсолютных путей).
3. **Компьютер Б**: панель → «Импорт / экспорт» → вкладка «Импорт JSON» →
   «Выбрать файл…» → «Предпросмотр импорта» (diff) → стратегия → «Применить импорт».
   Перезапись существующих шаблонов требует явного подтверждения.

## Инструменты агента

`doc_templates_list`, `doc_templates_get`, `doc_templates_create`,
`doc_templates_update`, `doc_templates_delete`, `doc_templates_generate`,
`doc_templates_save_document`, `doc_templates_export`, `doc_templates_import`,
`doc_templates_type_list`, `doc_templates_type_add`, `doc_templates_type_update`,
`doc_templates_type_delete` — каждый с JSON Schema параметров и объявлением
`output { schema, render }` (требование реестра инструментов DSH). Мутирующие операции проходят штатный конвейер
разрешений DSH: если текущий пресет доступа требует подтверждения, DSH спросит
пользователя перед вызовом; запись в `<workspace>/docs/` дополнительно
ограничена песочницей файловой службы.

## Ограничения

- **Rантайм-файлы — ESM JavaScript с JSDoc-типами, а не `.ts`.** DSH загружает
  host-половину плагина нативным `import()` из профиля (физически это
  `node_modules` внутри профиля), а Node не применяет strip-types к файлам в
  `node_modules`; клиентская половина обязана быть предсобранным бандлом
  `window.__ModuleLoader__.load({id, factory})` и компиляции из TypeScript не
  проходит вовсе. Типы проверяются через `tsconfig.json` (`checkJs`) —
  `npx tsc --noEmit` в редакторе и CI. Это тот же подход, что у референсных
  плагинов DSH.
- **Mermaid** показывается как код с подсветкой; отрисовку диаграмм выполняет
  та среда, где открывается экспортированный Markdown (плагин не тянет
  mermaid-библиотеку и не делает сетевых запросов).
- Панель работает с сессией, открытой в основном окне (проектная привязка
  cwd-зависима, как принято в Harness); без сессии доступен просмотр с подсказкой.
- Встроенные шаблоны read-only — дублируйте, чтобы править.
- Вызов `/doc-templates …` оставляет command-запись в логе сессии (штатный
  механизм команд).

## Тесты

```bash
npm test
```

Регрессионный прогон с созданием тестовых документов: `node scripts/make-test-documents.mjs`
— создаёт `test-artifacts/workspace/docs/…` (документы из всех встроенных шаблонов,
шаблон и документы кастомного типа, конфликт имён, экспорт/импорт) и
`test-artifacts/regression-report.md`.

Покрыто: валидация и нормализация шаблонов; подстановка переменных
(обязательные/необязательные/по умолчанию), генерация имени файла и суффиксы
`_2/_3`; CRUD, фильтры, изоляция проектных шаблонов; экспорт/импорт (стратегии,
diff, явное подтверждение перезаписи); повреждение файла и
восстановление из резервной копии; миграции схемы (успех, копия до миграции,
откат при неудаче, будущая версия); e2e-цикл «создание → генерация → сохранение
в docs/ (включая конфликт имён и dryRun) → экспорт → импорт»; клиентский бандл
(регистрация через ModuleLoader, XSS-безопасность Markdown-рендера).

## План ручной проверки

1. Установить плагин в профиль, перезапустить DSH, открыть Web UI.
2. В левой панели появился элемент «Шаблоны документации»; клик открывает панель,
   список содержит 8 встроенных шаблонов, сгруппированных по типам.
3. Поиск «требования» сужает список; фильтры по типу/области/тегу и сортировка
   переключаются; кнопка «Обновить» перезагружает список.
4. «Просмотр» у «Схема архитектуры» — Markdown отрисован, Mermaid-блок виден
   как код, `{{project_name}}` подсвечен; «Копировать содержимое» кладёт текст
   в буфер.
5. «Сгенерировать» у «Требования к функциональности»: пустые обязательные поля
   дают понятную ошибку; после заполнения — предпросмотр; «Сохранить в docs/…»
   показывает относительный путь `docs/Требования…_<дата>.md`; после
   подтверждения файл появляется в `<workspace>/docs/`; повторное сохранение
   создаёт `…_2.md`.
6. «Новый шаблон»: создание с переменными; шаблон появляется в списке;
   редактирование и удаление (с подтверждением) работают.
7. «Дублировать» на встроенном шаблоне создаёт редактируемую копию.
8. «Импорт / экспорт»: экспорт всех → скачать JSON; импорт того же файла с
   предпросмотром; включить «Разрешить перезапись» и применить — обновления
   видны в diff; вкладка «Импорт .md/.txt» создаёт шаблон из файла.
9. Сузить окно до узкой ширины: панель остаётся пригодной, тулбар переносится.
10. Клавиатура: Tab/стрелки по списку, Enter — просмотр, Escape закрывает диалоги.
11. `/doc-templates status` показывает каталог хранилища и версии; ручное
    повреждение `templates.json` → перезапуск → панель работает, `status`
    сообщает о восстановлении/сохранённом файле.
12. Перенос: экспорт на этом компьютере, импорт на втором — набор совпадает.
