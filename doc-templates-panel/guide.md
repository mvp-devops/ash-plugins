# Руководство пользователя — плагин «Шаблоны документации»

Практический гайд по повседневной работе с плагином `doc-templates-panel` в Web UI
DeepSeek Harness и по его настройкам. Технические подробности (установка из исходников,
архитектура, тесты) — в [README.md](README.md).

---

## 1. Где найти плагин

После установки в профиль и перезагрузки страницы:

1. В **левой навигации** Web UI нажмите иконку документа — **«Шаблоны документации»**
   (идёт после штатных пунктов; иконка — лист с галочкой).
2. Откроется панель: список шаблонов, сгруппированный по типам, с поиском и фильтрами.

Панель работает через текущую сессию:

- **Глобальные шаблоны** доступны всегда.
- **Проектные шаблоны** привязаны к рабочей директории сессии — они видны, когда
  открытая сессия указывает на соответствующий проект. Без открытой сессии панель
  покажет подсказку; создавать/сохранять документы в `docs/` в этом случае нельзя.

## 2. Обзор панели

```
┌──────────────────────────────────────────────────────────┐
│ Шаблоны документации            Шаблонов: 9              │
│            [Типы…] [Импорт / экспорт] [Новый шаблон]     │
├──────────────────────────────────────────────────────────┤
│ [поиск…] [Все типы▾] [Все области▾] [Все теги▾] [сорт▾] │
│                                                          │
│ ТРЕБОВАНИЯ — 2                                           │
│  ▸ Требования к функциональности   [Сгенерировать] [⋯]   │
│  ▸ Нефункциональные требования     [Сгенерировать] [⋯]   │
│ …                                                        │
└──────────────────────────────────────────────────────────┘
```

- **Поиск** ищет по названию, описанию, тегам и содержимому (несколько слов = «все слова встречаются»).
- **Фильтры**: тип документации, область (глобальный/проектный), тег.
- **Сортировка**: по названию (А→Я) или по дате изменения (свежие сверху).
- **Клавиатура**: `Tab`/стрелки — переход между шаблонами, `Enter` — просмотр,
  `Escape` — закрыть диалог. Все кнопки имеют aria-подписи.
- Кнопка `⋯` у шаблона открывает меню: Просмотр, Сгенерировать, Редактировать,
  Дублировать, Экспортировать, Удалить. Двойной клик по строке — быстрый просмотр.
- **Внешний вид**: панель следует теме приложения. В светлой теме поверхности белые,
  основные кнопки («Новый шаблон», «Сгенерировать», «Сохранить»…) — синие с белым
  текстом; в тёмной теме используются штатные тёмные токены DSH.

Встроенные шаблоны помечены бейджем «встроенный» и **доступны только для чтения** —
чтобы что-то изменить, продублируйте шаблон (меню `⋯` → «Дублировать»).

## 3. Просмотр шаблона

Меню `⋯` → «Просмотр» (или `Enter` на строке):

- содержимое рендерится как Markdown: заголовки, таблицы, чек-листы, списки, цитаты;
- плейсхолдеры `{{имя}}` подсвечиваются синим;
- Mermaid-диаграммы показываются как код (отрисовать их может любая среда с поддержкой
  Mermaid после экспорта документа);
- кнопка **«Копировать содержимое»** кладёт исходный Markdown в буфер обмена.

## 4. Создание и редактирование шаблона

Кнопка **«Новый шаблон»** или меню `⋯` → «Редактировать»:

| Поле | Что указать |
|---|---|
| Название | человекочитаемое имя; из него строится имя файла документа |
| Тип | один из встроенных или ваших типов (см. раздел 5) |
| Область | «Глобальный» — виден во всех проектах; «Проектный» — привязывается к текущему workspace |
| Формат | `markdown` (по умолчанию) или `plaintext` (влияет на расширение файла `.txt`) |
| Описание, теги, версия, автор | метаданные для поиска и порядка |
| Содержимое | Markdown с плейсхолдерами `{{имя_переменной}}` |
| Переменные | ключ (латиница/цифры/`_.-`), подпись, флажок «обязательна», значение по умолчанию, подсказка |

**Панель форматирования** над полем содержимого работает с выделенным текстом,
как в Markdown-редакторах:

- **B** — полужирный `**…**`, *I* — курсив `*…*`, `‹›` — код `` `…` ``;
- `H2`, `H3` — заголовки разделов;
- `• —`, `1. —` — маркированный/нумерованный список;
- `☑` — чек-лист `- [ ] …`;
- `❝` — цитата, `▦` — таблица-заготовка, `{ }` — блок кода (``` … ```);
- `{{ }}` — вставить плейсхолдер, `🔗` — ссылка, `—` — горизонтальный разделитель.

Плейсхолдеры, объявленные в переменных, при генерации заменяются значениями.
Рекомендуемые системные имена: `{{project_name}}` и `{{date}}` — они заполняются
автоматически, если объявлены в переменных, но не указаны пользователем.

## 5. Свои типы документации

Кнопка **«Типы…»** в шапке панели:

- **встроенные типы** (Требования, Техническая спецификация, Схема/диаграмма,
  Технический проект, Тест-кейс, Протокол тестирования, Произвольный) — неизменяемы;
- **пользовательские типы**: введите название (например, «Пользовательская история»)
  и нажмите «Добавить тип» — id сгенерируется автоматически (`ctype:…`);
- тип можно переименовать; удалить — только если он не используется шаблонами
  (панель подскажет, какими именно);
- типы входят в экспорт/импорт — при переносе на другой компьютер ничего не теряется.

## 6. Генерация документа и сохранение в docs/

Меню `⋯` → «Сгенерировать» (или кнопка на строке):

1. Заполните переменные шаблона. Обязательные помечены `*`; подсказка — под полем.
   Незаполненные необязательные останутся в документе как `{{…}}`.
2. **«Показать документ»** — предпросмотр результата.
3. Дальше два пути:
   - **«Копировать документ»** — результат в буфере обмена;
   - **«Сохранить в docs/…»** — панель покажет итоговый путь и спросит подтверждение.

Файл сохраняется в `<workspace>/docs/` текущей сессии:

- каталог `docs/` создаётся автоматически;
- имя файла: `<Название шаблона>_<ГГГГ-ММ-ДД>.md`
  (например, `Требования к функциональности_2026-11-08.md`);
- если файл уже существует, добавляется суффикс `_2`, `_3`, …;
- показывается **относительный** путь, ничего вне workspace не записывается;
- запись проходит через штатную файловую службу DSH с её песочницей.

## 7. Импорт и экспорт (перенос между компьютерами)

Кнопка **«Импорт / экспорт»**:

**Экспорт**
- «Экспортировать все шаблоны» — скачается `doc-templates-export.json`
  (шаблоны + ваши типы; без секретов и абсолютных путей);
- «Экспортировать выбранные» — только пользовательские шаблоны из текущего списка.

**Импорт JSON**
1. Вкладка «Импорт JSON» → «Выбрать файл…» или вставьте JSON в поле.
2. Выберите стратегию:
   - **merge** — обновлять существующие и добавлять новые (по умолчанию);
   - **overwrite** — то же, но явный режим перезаписи;
   - **skip-existing** — существующие не трогать;
   - **create-copy** — импортируемые копии существующих создавать как новые шаблоны.
3. «Предпросмотр импорта» покажет diff (создание/обновление/новый тип).
4. Если импорт затрагивает существующие шаблоны — отметьте
   «Разрешить перезапись существующих шаблонов» и нажмите «Применить импорт».
   Перед применением автоматически создаётся резервная копия хранилища.

**Импорт .md / .txt**
- вкладка «Импорт .md / .txt» → выберите файл → укажите название, тип и область →
  «Создать шаблон из файла». Удобно, чтобы завести шаблон из готового документа.

**Перенос между компьютерами**: на компьютере А — «Экспортировать все шаблоны»,
передайте JSON любым способом, на компьютере Б — «Импорт JSON» → файл → предпросмотр →
«Применить импорт».

## 8. Хранилище и резервные копии

- Пользовательские шаблоны и типы лежат в **профиле DSH**:
  `$DSH_PROFILE_DIR/doc-templates-panel/templates.json`
  (обычно `~/.dsh/profiles/<профиль>/doc-templates-panel/templates.json`).
- Встроенные шаблоны — часть пакета плагина, в файл не пишутся и при обновлении
  плагина не перезаписываются.
- Состояние и копии: `/doc-templates status` или низ диалога «Импорт / экспорт»:
  версия схемы, число пользовательских шаблонов, список `doc-templates.backup-*.json`.
- **Восстановление**: кнопка «Восстановить из копии» (берёт самую свежую копию).
- Если файл хранилища повреждён — плагин не падает: повреждённый файл сохраняется
  рядом (`doc-templates.corrupt-*.json`), выполняется автоматическое восстановление
  из последней копии, а панель объясняет, что произошло.
- Миграции схемы (`schemaVersion`) выполняются автоматически; перед миграцией
  создаётся резервная копия, при неудаче данные откатываются.

```
/doc-templates help
/doc-templates list   {"query":"требования","type":"requirements","sort":"updatedAt"}
/doc-templates get    {"id":"seed-test-case"}
/doc-templates create {"template":{"name":"…","type":"custom","scope":"global","content":"…"}}
/doc-templates update {"id":"…","patch":{"description":"…"}}
/doc-templates delete {"id":"…"}
/doc-templates duplicate {"id":"…","name":"Моя копия"}
/doc-templates generate {"id":"…","values":{"project_name":"Альфа"}}
/doc-templates save-document {"id":"…","values":{…},"dryRun":true}
/doc-templates export {"all":true}            # или {"ids":["…"]}
/doc-templates import  {"document":{…},"strategy":"merge","apply":true,"confirmOverwrite":false}
/doc-templates restore-backup                  # или {"backup":"doc-templates.backup-….json"}
/doc-templates status
/doc-templates type-list
/doc-templates type-add   {"label":"Пользовательская история"}
/doc-templates type-update {"id":"ctype:…","label":"User Story"}
/doc-templates type-delete {"id":"ctype:…"}
```

## 10. Инструменты агента

В беседе агент может работать с шаблонами сам — попросите его, например:
«сгенерируй протокол тестирования из шаблона и сохрани в docs/».
Доступные инструменты: `doc_templates_list`, `doc_templates_get`,
`doc_templates_create`, `doc_templates_update`, `doc_templates_delete`,
`doc_templates_generate`, `doc_templates_save_document`, `doc_templates_export`,
`doc_templates_import`, `doc_templates_type_list`, `doc_templates_type_add`,
`doc_templates_type_update`, `doc_templates_type_delete`.

Мутирующие вызовы проходят штатный конвейер разрешений DSH: если текущий пресет
доступа требует подтверждения, DSH спросит вас перед выполнением.

## 11. Настройки

Плагин не требует обязательной настройки. Единственный параметр — каталог
хранилища внутри профиля (по умолчанию `doc-templates-panel`), задаётся в
`cordis.patch.yml` при установке:

```yaml
- insert:
    - id: doc-templates-panel
      name: '@local/doc-templates-panel'
      config:
        directory: doc-templates-panel
```

Остальное поведение (панель, инструменты, команда) включается вместе с bundle —
управлять им можно в «Настройки → Плагины» (включить/выключить плагин целиком).

## 12. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Панель не видна в левой навигации | Проверьте «Настройки → Плагины»: bundle `@local/doc-templates-panel` включён; обновите страницу |
| «Откройте сессию с рабочей директорией» | Откройте или создайте сессию с проектом — панель работает через неё |
| «Шаблон не найден» после переноса | Импортируйте JSON-экспорт (раздел 7); проектные шаблоны видны только в соответствующем проекте |
| «Не заполнены обязательные переменные» | Заполните поля, помеченные `*`, в форме генерации |
| «Тип используется шаблонами» при удалении типа | Смените тип у перечисленных шаблонов и повторите |
| Файл хранилища повреждён | `/doc-templates restore-backup` или кнопка «Восстановить из копии» |
| Панель показывает «Ошибка интерфейса панели» | Нажмите `↺` в сообщении — панель продолжит работу без перезагрузки страницы; если ошибка повторяется на том же действии — обновите страницу (F5) и сообщите об ошибке |
| Документ не сохранился в docs/ | У сессии должна быть рабочая директория; проверьте, что политика разрешений DSH не заблокировала запись |

## 13. Частые вопросы

**Чем глобальный шаблон отличается от проектного?**
Глобальный виден во всех проектах. Проектный — только в сессиях с той рабочей
директорией, где он был создан (привязка хранится как хеш каталога, сам путь не сохраняется).

**Можно ли править встроенные шаблоны?**
Напрямую — нет. Продублируйте их: копия полностью редактируема.

**Куда попадают сгенерированные документы?**
В `<workspace>/docs/` сессии. Это обычные файлы проекта — их можно коммитить.

**Плагин выходит в сеть?**
Нет. Всё работает локально: хранение, генерация, импорт/экспорт.

**Как обновить плагин без потери данных?**
Просто установите новую версию: пользовательские данные живут в профиле DSH,
встроенный слой читается из пакета. Миграции выполняются автоматически с резервной копией.

**Панель выглядит не как остальные страницы (цвета/отступы)?**
Панель использует штатные токены темы DSH: в светлой теме — белые поверхности и
синие основные кнопки, в тёмной — тёмные. Верх панели автоматически учитывает
системные кнопки окна на macOS. Если после обновления плагина цвета не изменились —
обновите страницу (F5): клиентский бандл загружается заново по ревизии.
